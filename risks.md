# EmbArch: fleet risks

**Status:** active, 2026-09-03. The risk register for [protocol.md](protocol.md), split out of its §12 on 2026-09-03 when that doc got too long to read whole. Read it after the protocol, not instead of it. *(This line cited DOC-COMPACTION.md §3 until 2026-09-05, as though a cap had refused the edit. None had: that rule covers `embarch-doc` and nothing walked this repo. `scripts/check-fleet-doc-size.py` is what makes the citation true, and `deploy.py` runs it.)*

Bare `§N` references below are sections of [protocol.md](protocol.md); anything else names its doc.

These are **stated rather than designed away**: each one is a cost the owner accepted, and the entry says what it buys and what its failure looks like. A new one is added when a design choice trades safety for reach; an old one is removed only when the mechanism that made it a risk is gone, not when it has merely not fired yet.

- **Nothing reads a diff for intent *before* it lands.** **Amended 2026-09-04:** an `embarch-reviewer` now reads every unit's diff against its decisions *alongside* landing, so a contradiction is caught minutes after rather than never — but it still lands first, by design, because merge-on-green was chosen over a blocking review. The residue is that the window is short instead of infinite, and that a reviewer skipped for budget leaves it infinite again for that unit. Full delegate plus a mechanical gate plus 4–6 parallel branches means `main` across eight repos moves on green alone. §10's shared-crate/wire-type/retirement carve-out is the mitigation and is deliberately narrow. Watch for the first change that passes every check and contradicts a locked-in decision — that is this design's characteristic failure, and it will not announce itself.
- **Nobody watches the relay.** A leg ends and the next begins with no human in the loop and nothing in common but a written entry. An entry that omits something — a rebase that has not settled, a task blocked for a reason that will recur, a parked `suite` task's remaining window — is a fact the successor cannot recover, and it will act confidently without it.
- **The heartbeat is suppressed exactly when it is needed most.** `CronCreate`'s contract is that a job fires only while the REPL is idle, never mid-query, so the listener's 10-minute fallback is unavailable for as long as a tick runs. [fleet.md](../embarch-doc/.claude/commands/fleet.md)'s STEP 2 now makes one spawn attempt and ends the turn, which keeps that window short and lets the next tick retry — but that only covers a tick that **fails**. A tick that **hangs** on a tool call never returns to idle, and no prompt text can reach it: the fleet stays dark, the pump stays latched, and `fleet stop` cannot be delivered either, because a listener mid-query cannot read the channel. Nothing detects this from inside the process, and [ops](ops.md) §3 rules out anything outside it — a watchdog that survives VS Code closing would take away the kill switch. **Mitigated 2026-09-04, not closed:** the listener touches a tick file at the end of every tick and a report-only watchdog window (`/fleet watch`) alerts when it goes stale by 25 minutes. That window can alert and delete the pump latch, and nothing else — stop, never start — so the kill switch is unchanged; an action that only ever stops cannot take a stop away. It detects silence, cannot distinguish a hung tick from a closed window from a slept machine, and is not a stop channel — if the listener is wedged nobody can deliver a stop. It turns five hours into ten minutes; it does not turn a wedge into a recovery.
- **A red gate does not stop the pump** (§6), chosen for progress over caution. A broken `main`, a bad shared-crate merge or a toolchain problem burns one unit per failure until someone reads the channel. The supervisor is told to shout on a repeat, which is a discipline, not a mechanism. **Left a discipline on purpose, 2026-09-05.** A `blocked-since` reader over the last N entries would turn a cross-leg repeat into one line at step 0, and it is a good shape — but this register prefers a mechanism to a discipline *where the risk has fired*, and this one never has: across eleven legs and eighteen entries every `**Blocked:**` line reads `none`, and the only other string matching in this file is §11's own template. **Zero blocked units is the whole population**, so a mechanism built now would be calibrated against nothing, which is a mistake [ops](ops.md) §2 is already living with. **The trigger is the first repeat**: a second unit blocked by a failure a previous entry already named. Build it then, when there is a real signature to key on.
- **The listener's context grows, just slowly** — a few hundred tokens per wake, and it wakes on every heartbeat and every leg end. "Zero-context" is intent, not a property anything enforces: one message that pulls it into reading the repo undoes it, which is why §2 gives it no hands. It can be `/clear`ed without disarming (cron survives a clear), so a drifted listener is cheap to reset.
- **The budget's data source lives outside every repo, and half of that is now closed.** `scripts/usage-budget.py` is committed here, and so — since 2026-09-04 — is its feeder: `statusline-usage.py` is in [scripts/](scripts/), `~/.claude/settings.json`'s `statusLine` runs *that* copy, and `usage-budget.py` asserts the two match and says so when they do not. **The residue is the settings file itself**, which is in no repo and covered by no check: a machine reinstall or an edited `statusLine` block still turns every leg DEGRADED, and DEGRADED is indistinguishable from the steady state ([ops](ops.md) §2). The assertion makes that visible to anyone who runs the budget; nothing makes it visible to anyone who does not.
- **An agent now writes the instance's generated files, at a leg boundary.** `deploy.py --queue` pins a framework SHA and the listener spawns an `embarch-deployer` that runs `--from-latch`; that agent commits `.claude/`, the protocol READMEs and the shims into `embarch-doc` and pushes both repos. Until 2026-09-06 no agent could write those paths at all, and [ops](ops.md) §5.1's "there is no route from Slack to a standing rule" was true without qualification. **It is still true of authorship and that is the whole defence**: the deployer renders a commit the owner already made in a repo no leg ever checks out, a HEAD past the pin is a refusal rather than a fresher deploy, and every liveness check except the pump latch still applies. What was traded is that the *route* now exists where it did not — a rogue commit in `embarch-fleet` plus a rewritten latch would reach the instance unattended, where before it needed the owner's own hands. Bought for **~3.7 h of the ~6.6 h dead time** in the 14 h window ending 2026-09-06: the fleet stopped so the owner could hold the pen. Watch for a deploy landing that the owner does not recognise from his own `--queue`, and for a red gate leaving the instance rendered-and-uncommitted for longer than one boundary.
- **Refill now fires on a low-water mark, so a sweep can run while the queue has work.** It fired at zero until 2026-09-06, which was cheap and starved the wave: measured over the 7.2 h continuous run ending that morning, the queue held one or zero dispatchable tasks for 53% of it. The new gate (`queue-status.py --refill-owed`) trades sweeps for depth, and the sweep is the expensive half of a leg's step 1. If legs start spending materially more time in refill than in units — or if the queue grows faster than the fleet drains it, filling with work nobody chose — the threshold is `units_per_leg` and is the thing to move.
- **The pump latch is a file, so it can be wrong.** `embarch/.fleet/pump` outlives a killed leg on purpose, so it also outlives a killed machine. Arming deletes it; nothing else guarantees it matches what the owner last asked for.
- **The supervisor executes cross-repo passes unattended.** §8's reasoning is sound and its blast radius is still the largest in the suite. Announce-and-park narrows the window rather than closing it: an owner who does not read it inside 30 minutes gets the change anyway, which is what full delegation means.
- **A worker's design authority is scoped by repo, not by consequence.** A one-repo change can be less reversible than a two-repo rename — a wire encoding, a retired decision, a deleted doc. Scope was chosen because it is mechanically checkable; where it is the wrong boundary will show up in [embarch-decision-reversals.md](../embarch-doc/embarch-decision-reversals.md).
- **The queue is a view of the docs and can drift from them.** Refill reconciles in one direction only, and now runs only when the queue drains (§4), so drift lasts longer than it used to.
- **Worktrees are load-bearing and bit this suite once.** A naive repo-wide source scan finds `.claude/worktrees/` copies and silently over-extracts (`embarch-study-designer` decision 57). Any tool that walks a repo must honor ignore files.
- **`status.d/` can be skipped silently.** A worker that ships without a fragment leaves a suite-level doc stale and nothing fails. `check-ownership.py` proves it did not edit a shared doc; nothing proves it *should* have asked to. `check-staleness.py` catches part of it, heuristically, for two tables.
- **The owner's session, the listener and the supervisor were one context until 2026-09-03.** It ran batches, listened to Slack, and wrote the rules the supervisor obeys — amending standing rules and `scripts/` repeatedly, legitimately, with nothing structural marking the boundary, which is how three "documentation shaped exactly like the data it documents" defects shipped and were then caught only by the machinery they broke. Split into three ([ops](ops.md) §8.1). **The residue is that a leg run inline, which the owner may still ask for, puts them back in one context.**
- **Work can start from Slack outside the protocol.** A message that is not a `fleet` command is acted on by a spawned agent with the owner's authority ([ops](ops.md) §5.3) — no task file, no ownership map, no gate. Chosen deliberately for the reach it buys; it means the three mechanisms §3 and §10 exist to enforce have a documented way around them, bounded only by who sent the message.
- **A worker's two branches can land apart.** The code lands, the doc branch fails its gate, and the suite ships an undocumented change — the failure §5.1's pairing is meant to prevent, and which only the supervisor's discipline actually prevents.
- **The usage budget is calibrated against nothing.** [ops](ops.md) §2's thresholds and its taper are guesses until many legs have run.
- **Closed 2026-09-04 — `git add -A` in the main checkout.** `fold-commit.py` stages by explicit path and refuses anything outside a unit's own set, and a leg now works in its own worktree, so the owner's tree is not the fleet's. Kept here rather than deleted because the original entry named the real mechanism: **what made one checkout safe was a fact about the owner, not the design.** Original text: `git add -A` in the main checkout sweeps up whatever else is mid-edit. Workers are in worktrees (§5.1), but the supervisor folds in the main checkout, and under the relay that window is open continuously rather than once per batch. What makes one checkout safe is a fact about the owner, not the design: **they do not work in these repos while the fleet runs** (stated 2026-09-03), and their one concurrent write is a drop into `inbox/` — which still needs `git add inbox/<file>`, not `-A`.
