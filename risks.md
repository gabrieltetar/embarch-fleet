# EmbArch: fleet risks

**Status:** active, 2026-09-03. The risk register for [protocol.md](protocol.md), split out of its §12 on 2026-09-03 when that doc reached its size cap ([DOC-COMPACTION.md](../embarch-doc/DOC-COMPACTION.md) §3). Read it after the protocol, not instead of it.

Bare `§N` references below are sections of [protocol.md](protocol.md); anything else names its doc.

These are **stated rather than designed away**: each one is a cost the owner accepted, and the entry says what it buys and what its failure looks like. A new one is added when a design choice trades safety for reach; an old one is removed only when the mechanism that made it a risk is gone, not when it has merely not fired yet.

- **Nothing reads a diff for intent before it lands, most of the time.** Full delegate plus a mechanical gate plus 4–6 parallel branches means `main` across eight repos moves on green alone. §10's shared-crate/wire-type/retirement carve-out is the mitigation and is deliberately narrow. Watch for the first change that passes every check and contradicts a locked-in decision — that is this design's characteristic failure, and it will not announce itself.
- **Nobody watches the relay.** A leg ends and the next begins with no human in the loop and nothing in common but a written entry. An entry that omits something — a rebase that has not settled, a task blocked for a reason that will recur, a parked `suite` task's remaining window — is a fact the successor cannot recover, and it will act confidently without it.
- **The heartbeat is suppressed exactly when it is needed most.** `CronCreate`'s contract is that a job fires only while the REPL is idle, never mid-query, so the listener's 10-minute fallback is unavailable for as long as a tick runs. [fleet.md](../embarch-doc/.claude/commands/fleet.md)'s STEP 2 now makes one spawn attempt and ends the turn, which keeps that window short and lets the next tick retry — but that only covers a tick that **fails**. A tick that **hangs** on a tool call never returns to idle, and no prompt text can reach it: the fleet stays dark, the pump stays latched, and `fleet stop` cannot be delivered either, because a listener mid-query cannot read the channel. Nothing detects this from inside the process, and [ops](ops.md) §3 rules out anything outside it — a watchdog that survives VS Code closing would take away the kill switch. So the mitigation is the owner noticing channel silence, and on 2026-09-03 that took five hours.
- **A red gate does not stop the pump** (§6), chosen for progress over caution. A broken `main`, a bad shared-crate merge or a toolchain problem burns one unit per failure until someone reads the channel. The supervisor is told to shout on a repeat, which is a discipline, not a mechanism.
- **The listener's context grows, just slowly** — a few hundred tokens per wake, and it wakes on every heartbeat and every leg end. "Zero-context" is intent, not a property anything enforces: one message that pulls it into reading the repo undoes it, which is why §2 gives it no hands. It can be `/clear`ed without disarming (cron survives a clear), so a drifted listener is cheap to reset.
- **The budget's data source lives outside every repo and is unversioned.** `scripts/usage-budget.py` is committed here, but the thing that feeds it — `~/.claude/statusline-usage.py`, plus the `statusLine` block in `~/.claude/settings.json` — is not in any repo, has no history, and is not covered by any check. A machine reinstall, an edit, or a settings change silently turns every leg DEGRADED, and DEGRADED is indistinguishable from the steady state ([ops](ops.md) §2), so nothing would report it. Moving the script into `scripts/` and pointing settings at it would fix this and is not done.
- **The pump latch is a file, so it can be wrong.** `embarch/.fleet/pump` outlives a killed leg on purpose, so it also outlives a killed machine. Arming deletes it; nothing else guarantees it matches what the owner last asked for.
- **The supervisor executes cross-repo passes unattended.** §8's reasoning is sound and its blast radius is still the largest in the suite. Announce-and-park narrows the window rather than closing it: an owner who does not read it inside 30 minutes gets the change anyway, which is what full delegation means.
- **A worker's design authority is scoped by repo, not by consequence.** A one-repo change can be less reversible than a two-repo rename — a wire encoding, a retired decision, a deleted doc. Scope was chosen because it is mechanically checkable; where it is the wrong boundary will show up in [embarch-decision-reversals.md](../embarch-doc/embarch-decision-reversals.md).
- **The queue is a view of the docs and can drift from them.** Refill reconciles in one direction only, and now runs only when the queue drains (§4), so drift lasts longer than it used to.
- **Worktrees are load-bearing and bit this suite once.** A naive repo-wide source scan finds `.claude/worktrees/` copies and silently over-extracts (`embarch-study-designer` decision 57). Any tool that walks a repo must honor ignore files.
- **`status.d/` can be skipped silently.** A worker that ships without a fragment leaves a suite-level doc stale and nothing fails. `check-ownership.py` proves it did not edit a shared doc; nothing proves it *should* have asked to. `check-staleness.py` catches part of it, heuristically, for two tables.
- **The owner's session, the listener and the supervisor were one context until 2026-09-03.** It ran batches, listened to Slack, and wrote the rules the supervisor obeys — amending standing rules and `scripts/` repeatedly, legitimately, with nothing structural marking the boundary, which is how three "documentation shaped exactly like the data it documents" defects shipped and were then caught only by the machinery they broke. Split into three ([ops](ops.md) §8.1). **The residue is that a leg run inline, which the owner may still ask for, puts them back in one context.**
- **Work can start from Slack outside the protocol.** A message that is not a `fleet` command is acted on by a spawned agent with the owner's authority ([ops](ops.md) §5.3) — no task file, no ownership map, no gate. Chosen deliberately for the reach it buys; it means the three mechanisms §3 and §10 exist to enforce have a documented way around them, bounded only by who sent the message.
- **A worker's two branches can land apart.** The code lands, the doc branch fails its gate, and the suite ships an undocumented change — the failure §5.1's pairing is meant to prevent, and which only the supervisor's discipline actually prevents.
- **The usage budget is calibrated against nothing.** [ops](ops.md) §2's thresholds and its taper are guesses until many legs have run.
- **`git add -A` in the main checkout sweeps up whatever else is mid-edit.** Workers are in worktrees (§5.1), but the supervisor folds in the main checkout, and under the relay that window is open continuously rather than once per batch. What makes one checkout safe is a fact about the owner, not the design: **they do not work in these repos while the fleet runs** (stated 2026-09-03), and their one concurrent write is a drop into `inbox/` — which still needs `git add inbox/<file>`, not `-A`.
